# Specs do projeto

Cada mudança deve ter uma spec com quatro partes:

- **Contexto:** por que a mudança é necessária e qual problema resolve.
- **Tarefa:** o comportamento ou resultado esperado.
- **Regras:** restrições funcionais, técnicas e arquiteturais aplicáveis.
- **Definição de pronto:** critérios verificáveis para considerar a mudança concluída.

Esta pasta só entra no contexto de trabalho quando o agente for instruído explicitamente a ler a spec correspondente. Ao receber essa instrução, o agente deve ler a spec antes de planejar e implementar.
